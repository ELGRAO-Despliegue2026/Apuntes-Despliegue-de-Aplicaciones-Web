    Actividades

    Ejercicio de preguntas teóricas para repasar los conceptos de esta unidad, organizadas según los criterios de evaluación del RA3.

    CE a) Componentes y funcionamiento del servidor de aplicaciones

    1. ¿Qué diferencia fundamental existe entre un servidor web y un servidor de aplicaciones?
    2. ¿Qué es un conector en Tomcat y qué dos protocolos principales puede usar?
    3. ¿Qué representa el Contexto (Context) dentro de la arquitectura de Tomcat?
    4. ¿Para qué sirve un pool de conexiones a bases de datos?

    CE b) Archivos de configuración y bibliotecas compartidas

    1. ¿Qué fichero de Tomcat es equivalente, en cuanto a su función, al apache2.conf de Apache HTTP Server?
    2. ¿Dónde se definen los usuarios y roles de acceso al Manager de Tomcat?
    3. ¿Qué diferencia hay entre colocar una librería .jar en lib/ (del servidor) o en WEB-INF/lib/ (de la aplicación)?
    4. ¿Qué variable de entorno indica la ruta de instalación de la JVM?

    CE c) Cooperación con el servidor web

    1. ¿Por qué es recomendable colocar Apache HTTP Server delante de Tomcat en producción?
    2. ¿Qué diferencia hay entre usar mod_proxy_http y mod_jk para conectar Apache con Tomcat?
    3. ¿Qué hace la directiva ProxyPassReverse?
    4. ¿Qué riesgo de seguridad tuvo el protocolo AJP y cómo se mitiga?

    CE d) Mecanismos de seguridad

    1. ¿Qué es un Valve en Tomcat y para qué se usó en el ejemplo de restricción por IP?
    2. ¿Qué elementos se definen en un security-constraint dentro de web.xml?
    3. ¿Qué es un keystore y para qué se utiliza al configurar HTTPS directamente en Tomcat?
    4. Cita al menos tres buenas prácticas de seguridad recomendadas para un servidor de aplicaciones en producción.

    CE e) Componentes web del servidor de aplicaciones

    1. ¿Qué diferencia hay entre un Servlet y una página JSP?
    2. ¿Para qué se utiliza un Filter en una aplicación Java web?
    3. ¿Qué cookie utiliza Tomcat para identificar la sesión de un usuario?
    4. ¿Qué ventaja aporta definir un recurso JNDI en lugar de poner las credenciales de la base de datos directamente en el código?

    CE f) Despliegue de aplicaciones

    1. ¿Qué es un fichero .war y qué contiene?
    2. Indica dos formas distintas de desplegar una aplicación en Tomcat.
    3. ¿Qué ocurre si renombras tu aplicación como ROOT.war?
    4. ¿Por qué no es buena práctica incluir las credenciales de la base de datos directamente dentro del WAR?

    CE g) Pruebas de funcionamiento y rendimiento

    1. ¿Qué comando usarías para comprobar que Tomcat está escuchando en el puerto 8080?
    2. ¿Para qué sirven las opciones -c cookies.txt y -b cookies.txt de curl?
    3. ¿Qué diferencia hay entre Thread Group, HTTP Request y Listener en un plan de pruebas de JMeter?
    4. ¿Qué información aporta el comando jstat -gc?

    CE h) Documentación del servidor

    1. ¿Por qué es importante documentar los puertos y conectores configurados en un servidor de aplicaciones?
    2. ¿Qué información mínima debería incluir la documentación de una aplicación desplegada (más allá del propio código)?
    3. ¿Por qué se recomienda mantener la documentación del servidor versionada junto con el código de la aplicación?

    CE i) Virtualización y contenedores

    1. ¿Qué diferencia principal existe entre una máquina virtual y un contenedor?
    2. ¿Qué ventaja aporta crear una imagen Docker propia (Dockerfile) frente a usar directamente la imagen oficial de Tomcat sin modificar?
    3. ¿Qué papel juega docker-compose a la hora de desplegar Tomcat junto con una base de datos?
    4. Cita dos opciones de despliegue en la nube para un servidor de aplicaciones contenerizado.

    Caso práctico (reflexión final)

    Imagina que debes desplegar una aplicación Java de gestión de pedidos, con un panel de administración en /admin, que se conecta a una base de datos MySQL. Describe, de forma razonada, cómo aplicarías todos los conceptos vistos en esta unidad: estructura de ficheros, cooperación con Apache, seguridad, componentes web utilizados, proceso de despliegue, pruebas a realizar, documentación a generar y si lo desplegarías en un servidor tradicional o en un contenedor (justificando tu elección).
