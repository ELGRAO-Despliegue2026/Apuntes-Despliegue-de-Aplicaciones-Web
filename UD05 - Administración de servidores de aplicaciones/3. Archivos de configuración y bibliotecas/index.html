    Archivos de configuración y bibliotecas compartidas

    Instalación de Apache Tomcat

    sudo apt update
sudo apt install default-jdk -y
java -version

wget https://dlcdn.apache.org/tomcat/tomcat-10/v10.1.x/bin/apache-tomcat-10.1.x.tar.gz
sudo tar -xzf apache-tomcat-10.1.x.tar.gz -C /opt
sudo mv /opt/apache-tomcat-10.1.x /opt/tomcat

    Tip

    También se puede instalar mediante el gestor de paquetes (sudo apt install tomcat10), aunque la instalación manual desde el .tar.gz permite más control sobre la versión y la ubicación.

    Estructura de directorios de Tomcat

    Directorio Contenido
    bin/ Scripts de arranque/parada (startup.sh, shutdown.sh, catalina.sh)
    conf/ Ficheros de configuración principal del servidor
    lib/ Bibliotecas compartidas (.jar) disponibles para todas las aplicaciones
    logs/ Ficheros de log del servidor (catalina.out, localhost_access_log...)
    webapps/ Directorio donde se despliegan las aplicaciones web (.war)
    work/ Ficheros temporales generados en tiempo de ejecución (JSP compiladas...)
    temp/ Ficheros temporales de la JVM

    Principales ficheros de configuración (conf/)

    server.xml

    Es el fichero de configuración central del servidor, equivalente al apache2.conf de Apache HTTP Server. Define los conectores, los motores, los hosts virtuales...

    <Server port="8005" shutdown="SHUTDOWN">
  <Service name="Catalina">

    <!-- Conector HTTP -->
    <Connector port="8080" protocol="HTTP/1.1"
               connectionTimeout="20000"
               redirectPort="8443" />

    <!-- Conector AJP (usado para cooperar con Apache) -->
    <Connector protocol="AJP/1.3" address="::1"
               port="8009"
               secretRequired="false" />

    <Engine name="Catalina" defaultHost="localhost">
      <Host name="localhost" appBase="webapps"
            unpackWARs="true" autoDeploy="true">
      </Host>
    </Engine>
  </Service>
</Server>
    • port="8005" shutdown="SHUTDOWN": puerto de administración por el que Tomcat escucha el comando de apagado.
    • Connector port="8080": puerto HTTP por defecto de Tomcat.
    • Connector protocol="AJP/1.3" port="8009": conector AJP, utilizado para comunicarse con un servidor web (Apache HTTP) delante de Tomcat.
    • Host name="localhost" appBase="webapps": define el host virtual y el directorio base donde se despliegan las aplicaciones.

    web.xml

    Fichero de configuración que define el comportamiento por defecto de todas las aplicaciones web desplegadas (servlets globales, tipos MIME, páginas de bienvenida...). Cada aplicación puede tener también su propio web.xml dentro de WEB-INF/.

    <welcome-file-list>
    <welcome-file>index.html</welcome-file>
    <welcome-file>index.jsp</welcome-file>
</welcome-file-list>

    tomcat-users.xml

    Define los usuarios, contraseñas y roles utilizados por los mecanismos de autenticación de Tomcat y por el acceso al Manager (panel de administración web).

    <tomcat-users>
    <role rolename="manager-gui"/>
    <role rolename="admin-gui"/>
    <user username="admin" password="contraseña_segura" roles="manager-gui,admin-gui"/>
</tomcat-users>

    context.xml

    Configuración aplicable a nivel de contexto (aplicación), como la definición de recursos JNDI (fuentes de datos) o parámetros de la sesión.

    catalina.properties / catalina.policy

    • catalina.properties: propiedades generales del motor Catalina (classpath, paquetes permitidos...).
    • catalina.policy: políticas de seguridad de Java (Java Security Manager), que limitan lo que puede hacer el código de una aplicación (acceso a ficheros, red, etc.).

    Bibliotecas compartidas (lib/)

    El directorio lib/ contiene ficheros .jar disponibles para todas las aplicaciones desplegadas en el servidor, sin que cada una tenga que incluir su propia copia. Es habitual colocar aquí:

    • Drivers de bases de datos (ej. mysql-connector-j-x.x.x.jar, postgresql-x.x.x.jar).
    • Librerías comunes usadas por varias aplicaciones del mismo servidor.
    sudo cp mysql-connector-j-8.x.x.jar /opt/tomcat/lib/
sudo systemctl restart tomcat

    lib/ del servidor vs WEB-INF/lib/ de la aplicación

    Las bibliotecas colocadas en /opt/tomcat/lib/ son compartidas por todas las aplicaciones. Las que cada aplicación incluye dentro de su propio WEB-INF/lib/ (dentro del .war) solo están disponibles para esa aplicación concreta. Esto permite, por ejemplo, que dos aplicaciones usen versiones distintas de una misma librería sin interferir entre sí.

    Variables de entorno relevantes

    export JAVA_HOME=/usr/lib/jvm/default-java
export CATALINA_HOME=/opt/tomcat
export CATALINA_BASE=/opt/tomcat
    • JAVA_HOME: ruta de instalación de la JVM, necesaria para que Tomcat pueda ejecutarse.
    • CATALINA_HOME: ruta de instalación de Tomcat.
    • CATALINA_BASE: permite tener una instancia de configuración distinta de CATALINA_HOME, útil para ejecutar varias instancias de Tomcat compartiendo los mismos binarios.
