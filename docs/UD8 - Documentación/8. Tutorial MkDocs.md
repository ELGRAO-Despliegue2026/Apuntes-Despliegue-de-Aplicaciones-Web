# Tutorial: Crear un proyecto con MkDocs

**MkDocs** es un generador de sitios de documentación estática, rápido y sencillo, que convierte ficheros Markdown en un sitio web navegable. Es ampliamente utilizado para documentar proyectos software, precisamente el que se ha usado para generar estos apuntes.

## 1. Requisitos previos

- Tener instalado **Python 3** y `pip`.

```bash
python3 --version
pip3 --version
```

## 2. Instalación de MkDocs

Se recomienda trabajar dentro de un entorno virtual:

```bash
python3 -m venv venv
source venv/bin/activate   # En Windows: venv\Scripts\activate

pip install mkdocs
```

Comprobar la instalación:

```bash
mkdocs --version
```

(Opcional) Instalar el tema **Material for MkDocs**, uno de los más utilizados:

```bash
pip install mkdocs-material
```

## 3. Crear un nuevo proyecto

```bash
mkdocs new mi-documentacion
cd mi-documentacion
```

Esto genera la siguiente estructura:

```text
mi-documentacion/
├── docs/
│   └── index.md
└── mkdocs.yml
```

- `docs/`: carpeta donde se escriben los ficheros Markdown con el contenido.
- `mkdocs.yml`: fichero de configuración del sitio.

## 4. Configurar el fichero `mkdocs.yml`

```yaml
site_name: Mi Documentación
site_description: Documentación del proyecto X
site_author: Carles

theme:
  name: material
  language: es
  palette:
    primary: indigo
    accent: indigo
  features:
    - navigation.tabs
    - navigation.top
    - search.suggest

nav:
  - Inicio: index.md
  - Instalación: instalacion.md
  - Uso: uso.md

markdown_extensions:
  - admonition
  - toc:
      permalink: true
  - pymdownx.highlight
  - pymdownx.superfences
```

## 5. Añadir contenido

Crear nuevas páginas dentro de `docs/`:

```bash
echo "# Instalación" > docs/instalacion.md
echo "# Uso de la aplicación" > docs/uso.md
```

Editar `docs/index.md`:

```markdown
# Bienvenido

Esta es la documentación oficial del proyecto.

## Características

- Fácil de usar
- Documentación versionada con Git
- Publicada automáticamente con MkDocs
```

## 6. Previsualizar el sitio en local

```bash
mkdocs serve
```

Esto levanta un servidor local (por defecto en `http://127.0.0.1:8000`) con **recarga automática** cada vez que se guarda un cambio en un fichero Markdown.

## 7. Generar el sitio estático

```bash
mkdocs build
```

Se genera una carpeta `site/` con el sitio HTML final, listo para ser desplegado en cualquier servidor web.

## 8. Versionar el proyecto con Git

```bash
git init
echo "venv/" >> .gitignore
echo "site/" >> .gitignore
git add .
git commit -m "Proyecto inicial de documentación con MkDocs"
```

## 9. Publicar la documentación en GitHub Pages

Si el repositorio está alojado en GitHub:

```bash
git remote add origin https://github.com/usuario/mi-documentacion.git
git push -u origin main

mkdocs gh-deploy
```

El comando `mkdocs gh-deploy`:

1. Genera el sitio (`mkdocs build`).
2. Crea/actualiza la rama `gh-pages`.
3. Sube el contenido generado a esa rama.
4. GitHub Pages publica automáticamente el sitio.

La documentación quedará accesible en una URL del tipo:

```text
https://usuario.github.io/mi-documentacion/
```

## 10. Resumen de comandos principales

| Comando             | Descripción                                   |
|----------------------|-----------------------------------------------|
| `mkdocs new <nombre>`| Crea un nuevo proyecto de documentación       |
| `mkdocs serve`        | Previsualiza el sitio en local con recarga automática |
| `mkdocs build`        | Genera el sitio estático en la carpeta `site/`|
| `mkdocs gh-deploy`    | Publica el sitio en GitHub Pages              |

Con estos pasos se dispone de un flujo completo: **escritura de documentación en Markdown → control de versiones con Git → generación y publicación automática con MkDocs**.
