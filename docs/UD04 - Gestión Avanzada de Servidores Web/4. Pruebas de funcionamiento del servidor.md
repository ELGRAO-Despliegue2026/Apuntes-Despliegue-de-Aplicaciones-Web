# Pruebas de funcionamiento del servidor

Una vez configurado un servidor web (autenticación, HTTPS, VirtualHosts...) es imprescindible **comprobar que todo funciona correctamente** antes de darlo por válido. En este apartado veremos distintas herramientas y técnicas de prueba.

## Comprobación de sintaxis de la configuración

Antes de recargar Apache, conviene comprobar que la configuración no tiene errores:

```bash
sudo apache2ctl configtest
```

Si todo es correcto, debería mostrar `Syntax OK`.

## Comprobación del estado del servicio

```bash
sudo systemctl status apache2
sudo journalctl -u apache2 -n 50
```

## Comprobación de los puertos en escucha

```bash
sudo ss -tulnp | grep apache2
```

Debería mostrar el proceso escuchando en los puertos `80` y, si está configurado HTTPS, también en el `443`.

## Pruebas con `curl`

### Comprobar el código de estado devuelto

```bash
curl -I http://localhost
```

### Comprobar que la autenticación funciona correctamente

```bash
# Sin credenciales (debería devolver 401 Unauthorized)
curl -I http://localhost/privado/

# Con credenciales correctas (debería devolver 200 OK)
curl -I -u usuario1:contraseña http://localhost/privado/
```

### Comprobar HTTPS y el certificado

```bash
curl -vk https://localhost
```

La opción `-k` ignora errores de certificado (útil con certificados autofirmados en pruebas); en producción no debería usarse.

## Pruebas con herramientas de análisis online

- **[SSL Labs](https://www.ssllabs.com/ssltest/)**: analiza la configuración TLS de un servidor público y asigna una calificación (A, B, C...) según su seguridad.
- **[securityheaders.com](https://securityheaders.com)**: analiza las cabeceras de seguridad HTTP devueltas por el servidor.

## Pruebas de carga básicas con Apache Bench (`ab`)

Permite comprobar cómo responde el servidor ante múltiples peticiones simultáneas.

```bash
sudo apt install apache2-utils -y
ab -n 100 -c 10 http://localhost/
```

- `-n 100`: número total de peticiones.
- `-c 10`: número de peticiones simultáneas (concurrencia).

El resultado incluye información como el número de peticiones por segundo y el tiempo medio de respuesta.

## Revisión de logs

Los logs son fundamentales para detectar errores de configuración, intentos de acceso no autorizados o problemas de rendimiento.

```bash
sudo tail -f /var/log/apache2/access.log
sudo tail -f /var/log/apache2/error.log
```

## Checklist de comprobaciones antes de pasar a producción

- [ ] `apache2ctl configtest` sin errores.
- [ ] El servicio Apache está activo y habilitado al arranque.
- [ ] Los VirtualHosts responden con el contenido esperado.
- [ ] La autenticación configurada (si existe) bloquea correctamente el acceso no autorizado.
- [ ] HTTPS funciona y el certificado es válido (no autofirmado en producción).
- [ ] Los logs no muestran errores inesperados.
- [ ] El servidor ha sido sometido a una prueba de carga básica.
