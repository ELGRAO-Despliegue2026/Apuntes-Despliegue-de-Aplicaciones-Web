# Autenticación y control de acceso

Un servidor web no solo debe servir contenido, sino también **controlar quién puede acceder** a determinados recursos. Apache ofrece varios mecanismos para ello.

## Control de acceso básico mediante el fichero de configuración

Dentro de un bloque `<Directory>`, `<Location>` o `<Files>` podemos restringir el acceso según la **dirección IP** del cliente:

```text
<Directory /var/www/html/privado>
    Require ip 192.168.1.0/24
</Directory>
```

También se puede denegar el acceso a todos salvo a una excepción:

```text
<Directory /var/www/html/privado>
    Require all denied
    Require ip 127.0.0.1
</Directory>
```

La directiva `Require` sustituyó en Apache 2.4 a las antiguas directivas `Order`/`Allow`/`Deny` de Apache 2.2.

## Autenticación básica (Basic Authentication)

Permite proteger un recurso mediante **usuario y contraseña**. Las credenciales viajan codificadas en Base64 (no cifradas), por lo que **solo debe usarse sobre HTTPS**.

### Crear el fichero de contraseñas

```bash
sudo apt install apache2-utils -y
sudo htpasswd -c /etc/apache2/.htpasswd usuario1
```

Para añadir usuarios adicionales (sin el `-c`, que borraría el fichero):

```bash
sudo htpasswd /etc/apache2/.htpasswd usuario2
```

### Configurar la protección de un directorio

```text
<Directory /var/www/html/privado>
    AuthType Basic
    AuthName "Zona restringida"
    AuthUserFile /etc/apache2/.htpasswd
    Require valid-user
</Directory>
```

- `AuthType Basic`: tipo de autenticación.
- `AuthName`: texto mostrado en el cuadro de inicio de sesión del navegador.
- `AuthUserFile`: ruta al fichero con los usuarios y contraseñas (cifradas con un hash).
- `Require valid-user`: exige cualquier usuario válido del fichero.

## Autenticación digest (Digest Authentication)

Similar a la autenticación básica, pero las credenciales se envían como un **hash** en lugar de en texto Base64, ofreciendo algo más de seguridad, aunque hoy en día está en desuso en favor de HTTPS + Basic Auth.

```bash
sudo htdigest -c /etc/apache2/.htdigest "Zona restringida" usuario1
```

```text
<Directory /var/www/html/privado>
    AuthType Digest
    AuthName "Zona restringida"
    AuthUserFile /etc/apache2/.htdigest
    Require valid-user
</Directory>
```

## Combinando control de acceso por IP y autenticación

```text
<Directory /var/www/html/privado>
    AuthType Basic
    AuthName "Zona restringida"
    AuthUserFile /etc/apache2/.htpasswd
    Require valid-user
    Require ip 192.168.1.0/24
    <RequireAny>
        Require valid-user
        Require ip 127.0.0.1
    </RequireAny>
</Directory>
```

- `<RequireAny>`: se concede acceso si se cumple **al menos una** de las condiciones internas.
- `<RequireAll>`: se concede acceso solo si se cumplen **todas** las condiciones internas.

## Restringir el acceso con `.htaccess`

Si el `AllowOverride` del `<Directory>` lo permite, se puede colocar un fichero `.htaccess` dentro del propio directorio a proteger, con el mismo contenido que iría en el bloque de configuración:

```text
AuthType Basic
AuthName "Zona restringida"
AuthUserFile /etc/apache2/.htpasswd
Require valid-user
```

!!! warning
    El uso de `.htaccess` es cómodo pero **ralentiza** el servidor, ya que Apache debe comprobar su existencia en cada petición. Se recomienda usar la configuración centralizada (`sites-available`) siempre que sea posible.

## Buenas prácticas de autenticación

- Nunca usar **Basic Auth sin HTTPS** en producción.
- Usar contraseñas robustas y almacenarlas siempre con un hash (nunca en texto plano).
- Limitar el acceso también por **IP** cuando sea posible, como capa adicional de seguridad.
- Revisar periódicamente los usuarios con acceso a zonas restringidas.
