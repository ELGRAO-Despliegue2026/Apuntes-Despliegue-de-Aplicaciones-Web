# 2. Instalación y configuración

## ¿Qué es Git?

Git es un **sistema de control de versiones distribuido (DVCS)**. Permite:

- Guardar el historial completo de cambios de un proyecto.
- Trabajar en paralelo con otras personas sin pisarse el trabajo.
- Volver a versiones anteriores en caso de error.
- Trabajar sin conexión, ya que cada copia local contiene el historial completo (a diferencia de sistemas centralizados como SVN).

Se usa principalmente para código fuente, pero sirve para cualquier conjunto de archivos de texto.

## Instalación

=== "Linux (Debian/Ubuntu)"
    ```bash
    sudo apt update
    sudo apt install git
    ```

=== "Windows"
    Descargar el instalador desde [git-scm.com](https://git-scm.com) y seguir el asistente.

=== "macOS"
    ```bash
    brew install git
    ```

Comprobar la instalación:

```bash
git --version
```

## Inicializar un repositorio

```bash
git init
```

Este comando crea una carpeta oculta **`.git`** dentro del proyecto. Ahí se guarda **todo** lo que Git necesita: historial de commits, ramas, configuración local, etc. Si se borra `.git`, se pierde el control de versiones (los archivos del proyecto se mantienen, pero ya no habrá historial).

Archivos/carpetas principales dentro de `.git`:

| Elemento    | Descripción                                                |
| ----------- | ----------------------------------------------------------- |
| `HEAD`      | Puntero a la rama/commit actual.                             |
| `config`    | Configuración local del repositorio (usuario, remotos...).  |
| `objects/`  | Almacena los datos versionados (commits, árboles, blobs).   |
| `refs/`     | Referencias a ramas y tags.                                 |
| `index`     | Representa el **staging area** (ver siguiente apartado).    |

## Configuración de usuario

Antes de poder hacer `commit`, Git necesita saber **quién** hace los cambios:

```bash
git config --global user.name "Nombre Apellido"
git config --global user.email "correo@ejemplo.com"
```

- `--global` aplica la configuración a todos los repositorios del usuario en el equipo. Sin ese flag, se aplica solo al repositorio actual.
- Esta información se guarda en cada **commit** como autor, permitiendo saber quién hizo cada cambio.
- Es obligatorio configurarlo: sin nombre/email, Git rechaza el `commit` (el `add` sí funciona, ya que solo mueve archivos al staging).

Comprobar la configuración actual:

```bash
git config --list
```
