# Documentación de componentes software

En este apartado veremos cómo documentar código fuente utilizando generadores específicos de cada plataforma, a partir de comentarios estructurados en el propio código.

## Javadoc (Java)

Javadoc genera documentación HTML a partir de comentarios especiales `/** ... */` situados antes de clases, métodos y atributos.

```java
/**
 * Representa a un usuario del sistema.
 * @author Carles
 */
public class Usuario {

    /** Nombre del usuario */
    private String nombre;

    /**
     * Obtiene el nombre del usuario.
     * @return el nombre del usuario
     */
    public String getNombre() {
        return nombre;
    }
}
```

Para generar la documentación:

```bash
javadoc -d docs Usuario.java
```

## JSDoc (JavaScript)

JSDoc utiliza comentarios `/** ... */` con etiquetas como `@param` y `@returns`.

```javascript
/**
 * Suma dos números.
 * @param {number} a - Primer número.
 * @param {number} b - Segundo número.
 * @returns {number} La suma de a y b.
 */
function sumar(a, b) {
    return a + b;
}
```

Instalación y generación:

```bash
npm install -g jsdoc
jsdoc sumar.js -d docs
```

## phpDocumentor (PHP)

```php
/**
 * Calcula el precio con IVA.
 *
 * @param float $precio Precio sin IVA.
 * @return float Precio con IVA aplicado.
 */
function calcularPrecioConIva(float $precio): float {
    return $precio * 1.21;
}
```

```bash
phpdoc -d ./src -t ./docs
```

## Sphinx (Python)

Sphinx usa docstrings y el módulo `autodoc` para generar documentación automáticamente.

```python
def sumar(a: int, b: int) -> int:
    """
    Suma dos números enteros.

    :param a: primer número
    :param b: segundo número
    :return: la suma de a y b
    """
    return a + b
```

```bash
pip install sphinx
sphinx-quickstart
sphinx-build -b html source build
```

## Swagger / OpenAPI (documentación de APIs REST)

Permite describir endpoints, parámetros y respuestas de una API en un fichero YAML o JSON, generando documentación interactiva navegable.

```yaml
openapi: 3.0.0
info:
  title: API Usuarios
  version: 1.0.0
paths:
  /usuarios:
    get:
      summary: Lista todos los usuarios
      responses:
        '200':
          description: Lista de usuarios
```

## Buenas prácticas

- Documentar siempre el **propósito**, **parámetros** y **valor de retorno** de cada función/método.
- Mantener la documentación **actualizada** junto con el código (idealmente en el mismo commit).
- Integrar la generación de documentación en el proceso de **integración continua**.
