# Sistemas de control de versiones

Un **sistema de control de versiones (SCV)** permite registrar los cambios realizados sobre un conjunto de ficheros a lo largo del tiempo, de forma que se pueda recuperar cualquier versión anterior, comparar cambios y colaborar con otros desarrolladores.

Git es, hoy en día, el sistema de control de versiones distribuido más utilizado.

## Instalación de Git

### Linux (Debian/Ubuntu)

```bash
sudo apt update
sudo apt install git -y
git --version
```

### Windows

Descargar e instalar [Git for Windows](https://git-scm.com/download/win), que incluye Git Bash.

### macOS

```bash
brew install git
```

## Configuración inicial

```bash
git config --global user.name "Carles"
git config --global user.email "carles@example.com"
git config --global init.defaultBranch main
git config --list
```

## Creación y uso básico de un repositorio

```bash
# Crear un repositorio nuevo
mkdir mi-proyecto
cd mi-proyecto
git init

# Añadir ficheros al área de preparación (staging)
git add .

# Confirmar los cambios
git commit -m "Primer commit"

# Ver el estado del repositorio
git status

# Ver el historial de commits
git log
```

## Trabajo con repositorios remotos

```bash
# Clonar un repositorio remoto
git clone https://github.com/usuario/mi-proyecto.git

# Añadir un remoto a un repositorio existente
git remote add origin https://github.com/usuario/mi-proyecto.git

# Subir cambios al remoto
git push origin main

# Descargar cambios del remoto
git pull origin main
```

## Ramas (branches)

```bash
# Crear una nueva rama
git branch documentacion

# Cambiar de rama
git checkout documentacion

# Crear y cambiar en un solo paso
git checkout -b documentacion

# Fusionar una rama en main
git checkout main
git merge documentacion
```

## Flujo de trabajo colaborativo típico

1. Clonar el repositorio.
2. Crear una rama para la nueva funcionalidad o para la documentación.
3. Realizar cambios y confirmarlos con commits descriptivos.
4. Subir la rama al repositorio remoto (`git push`).
5. Abrir una **pull request / merge request**.
6. Revisión por parte de otros miembros del equipo.
7. Fusión (*merge*) en la rama principal.

## Resolución de conflictos

Cuando dos ramas modifican las mismas líneas, Git marca el conflicto en el fichero afectado:

```text
<<<<<<< HEAD
Contenido de la rama actual
=======
Contenido de la rama que se está fusionando
>>>>>>> documentacion
```

Es necesario editar manualmente el fichero, decidir qué contenido se mantiene, y después:

```bash
git add fichero-conflictivo.md
git commit
```

## Plataformas de alojamiento de repositorios

- **GitHub**
- **GitLab**
- **Bitbucket**

Estas plataformas añaden funcionalidades sobre Git: gestión de incidencias (*issues*), revisión de código (*pull/merge requests*), integración continua (CI/CD), wikis y páginas estáticas.
