# Herramientas colaborativas para la documentación

La documentación de un proyecto software suele ser elaborada y mantenida por varias personas. Por ello es necesario utilizar herramientas que faciliten el trabajo colaborativo.

## Wikis de plataformas de control de versiones

Tanto **GitHub** como **GitLab** ofrecen una wiki asociada a cada repositorio, versionada internamente con Git, donde cualquier colaborador con permisos puede crear y editar páginas en Markdown.

- GitHub Wiki
- GitLab Wiki

## Issues y Pull/Merge Requests como documentación

Las discusiones en *issues* y las revisiones en *pull requests* / *merge requests* documentan decisiones de diseño y cambios, quedando el historial accesible para todo el equipo.

## Google Docs / Google Sites

Permiten edición simultánea en tiempo real, control de comentarios y sugerencias, útil para documentación de carácter más funcional o de negocio.

## Confluence (Atlassian)

Herramienta orientada a equipos, con plantillas, control de versiones de páginas, permisos granulares y fuerte integración con Jira.

## Notion

Herramienta todo-en-uno que combina páginas de documentación, bases de datos y tableros, con edición colaborativa en tiempo real.

## MkDocs + repositorio Git como herramienta colaborativa

Al escribir la documentación en ficheros Markdown dentro del propio repositorio Git, se obtiene de forma gratuita:

- **Versionado** de cada cambio (quién, cuándo y qué se modificó).
- **Revisión por pares** mediante pull/merge requests.
- **Integración con CI/CD** para publicar automáticamente la documentación (por ejemplo con GitHub Pages o GitLab Pages).

## Buenas prácticas de colaboración

- Definir una **estructura y plantilla** común para todas las páginas.
- Establecer un **flujo de revisión** (quién aprueba los cambios).
- Mantener un **historial de cambios** (changelog).
- Usar **ramas** específicas para cambios importantes en la documentación.
- Asignar **responsables** de mantener actualizadas determinadas secciones.
